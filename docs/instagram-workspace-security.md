# Instagram workspace and staged D1 protection
The app picker and account-gated workspace link to the separate personal Instagram API origin, which has its own site password and encrypted session. Do not reuse or expose the shared site password in the public app. Official Instagram remains the login/safety fallback and moderation surface. No Instagram credentials or messages are copied to D1. The personal API provides feed, Reels, story and DM screens; direct media loads use HTTPS and an Instagram/Meta CDN allowlist.
## D1 migration (not deployed)
This branch adds versioned AES-256-GCM encryption for the checked-in cloudflare/auth history payload, with random 96-bit IVs, owner/version AAD and compare-and-swap migration of old rows on read. All new history writes are encrypted. Missing or invalid keys fail closed. Passwords remain salted scrypt hashes and session tokens remain hashed. User identifiers, indexes and operational metadata are not encrypted by this patch. Existing production Workers may differ from the repository; inventory both primary and secondary D1 schemas and route implementations before deployment.
1. Back up both D1 databases and verify restore.
2. Generate a 32-byte random base64url key (43 characters) locally, and configure HISTORY_ENCRYPTION_KEY as a Worker secret on each compatible Worker. For replicas sharing ciphertext, use the same protected key; do not commit or log it.
3. Run node --test tests/account-worker.test.mjs and verify the real Workers against staging databases. Deploy compatible readers to every replica before enabling encrypted writes.
4. Migrate unread legacy rows with a bounded audited migration and verify every row decrypts, then retire plaintext backups according to retention policy. Existing backups and inactive legacy rows are not automatically encrypted.
5. Do not roll back to plaintext-only readers after encrypted writes begin. Retain version-aware readers and protected keys; plan rotation and disaster recovery.
TLS protects transport; AES-GCM protects history payloads at the application layer. This is not end-to-end encryption. Full D1 coverage and live migration are not completed.
